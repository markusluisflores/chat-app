## 2026-06-10 — Session Summary

**Decisions:**
- Chose `PresenceContext` React context singleton over per-component Supabase channel subscriptions — `createBrowserClient` is a singleton and `supabase.channel()` reuses channels by topic, so three components subscribing to the same topic caused "cannot add presence callbacks after subscribe()" errors. A single provider owning the channel is the only safe pattern. See docs/adr/ADR-001-presence-context-singleton.md.
- Chose `channel.teardown() + (supabase.realtime as any)._remove(channel)` for Realtime cleanup over `supabase.removeChannel()` — the official API is async and leaves the channel in the internal array long enough for React Strict Mode's double-invoke to retrieve an already-subscribed instance. See docs/adr/ADR-005-realtime-channel-cleanup.md.
- Chose `mark_messages_read` as a security-definer RPC rather than loosening the UPDATE RLS policy — receivers need to update `read_at` on messages they received, but broadening the UPDATE policy would also let them modify message content. See docs/adr/ADR-004-mark-messages-read-rpc.md.
