## 2026-06-23 — Stale profile links + unread bold fixes

**Decisions:**
- Added `profiles` table to `supabase_realtime` publication (migration 008) — this was the root cause of issue #12. Supabase `postgres_changes` subscriptions silently receive no events for tables not listed in the publication, so the UPDATE listener in `ConversationList` never fired.

## 2026-07-07 — Railway Cloudflare rate limiting, E2E pipeline unblocked

**Decisions:**
- Railway's Cloudflare applies a strict 10 RPS rate limit to GraphQL requests that lack a `?queryName=` query parameter. Shared GitHub Actions runner IPs hit this limit (many users make Railway API calls from the same pool of IPs), triggering extended IP bans — presenting as `HTTP 403: error code: 1010`. The fix is to append `?queryName=<opName>` to every Railway GraphQL URL, which opts into the standard 50 RPS limit instead. This is documented in a Railway Central Station community thread on Cloudflare rate limiting. Applied to all three `gql()` calls in `e2e.yml`.
- Added `skip_var_set` workflow_dispatch input to `e2e.yml` — allows triggering E2E against a Railway environment whose vars are already correctly set (e.g. pre-configured via Railway MCP), bypassing the Railway GraphQL API entirely. This was the only way to test the `Point staging Supabase webhook` step since the Cloudflare ban was still active.
- Railway MCP (`railway mcp`) authenticates via browser OAuth, not `RAILWAY_TOKEN`. The session TTL is 1 hour. `railway login` must be run at the start of any session that uses Railway MCP. The `RAILWAY_TOKEN` in `.mcp.json` does not affect MCP auth — it's only relevant to non-MCP CLI commands. `.mcp.json` must also contain the current account token to avoid stale-token errors in other Railway CLI contexts.
- Worked around Supabase webhook step HTTP 403 in CI manually: ran the `CREATE OR REPLACE FUNCTION handle_message_insert_webhook()` SQL directly via Supabase MCP `execute_sql` on staging project `slhimmymdmfliiwshfjn`. Root cause of the 403 from `api.supabase.com/v1/projects/{ref}/database/query` is unknown — `SUPABASE_ACCESS_TOKEN` is present in GitHub Secrets (verified), but the API returns 403.
